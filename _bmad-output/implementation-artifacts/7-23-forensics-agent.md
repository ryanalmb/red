# Story 7.23: ForensicsAgent Implementation

Status: done

## Story

As a **developer**,
I want **a digital forensics agent that uses LLM-driven tool selection**,
so that **evidence collection and analysis is performed with expert-level tool selection (FR2, FR31, FR32)**.

## Acceptance Criteria

1. **Thin subclass architecture (agent-refactor-pattern v2)**
   - `ForensicsAgent` is a thin subclass of `StigmergicAgent` (<300 LOC target).
   - Constructor sets `role=AgentRole.FORENSICS`.
   - Constructor accepts `specialty` parameter (default: `"general"`).
   - Target is **NOT** accepted in the constructor; it is passed to `execute_forensics_collection(...)`.

2. **LLM-driven tool selection (no hardcoding)**
   - `execute_forensics_collection(target, context)` uses inherited `select_tool()`.
   - Tool commands are generated by LLM via inherited `generate_command()` (using tool `--help` output).
   - **Must not** contain `tool_sequence` or any `_generate_*_command()` helpers.

3. **Evidence collection + chain-of-custody metadata**
   - Agent collects relevant artifacts (as available in context):
     - filesystem artifacts (logs, configs, browser data),
     - memory artifacts (when memory image path is provided),
     - binary artifacts (suspicious files for carving/signature analysis).
   - Each collected artifact is recorded with chain-of-custody metadata including at minimum:
     - `artifact_id`, `source_target`, `collected_at` (UTC ISO), `collector_agent_id`,
     - `acquisition_method` (tool + command),
     - `sha256` of captured artifact (or of referenced file if already produced by tool),
     - `path` (where stored in the engagement evidence directory).

4. **Memory analysis support (if applicable)**
   - If a memory image path is present in `context`, the agent can select memory analysis tools (e.g., volatility) and produce findings.

5. **Stigmergic publication + decision context (NFR37 hard gate)**
   - Findings are published to `findings:{target_hash}:forensics`.
   - All created `AgentAction` records have **non-empty** `decision_context`.
   - Decision context includes at minimum: `initial_spawn:{agent_id}` and `target:{target}`.

6. **Preserve base stigmergic hooks**
   - `on_finding()`, `on_signal()`, `_flush_buffer()`, `stop()` behavior remains consistent with other agents.

7. **Quality gates**
   - Unit tests must achieve **100% coverage** for `src/cyberred/agents/forensics.py`.
   - Integration tests must exercise production code path (agent loop + tool execution boundary) with minimal mocking.
