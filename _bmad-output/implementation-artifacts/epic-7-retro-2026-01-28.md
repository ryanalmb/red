## ⚠️ Challenges & Patterns

### Root Cause: Architecture-to-Story Gap

The initial implementations (7.1, 7.3, 7.4, 7.5) followed the story specs but missed the architectural intent. The architecture doc specified LLM-driven tool selection, but the stories implied hardcoded sequences.

**Lesson Learned:** Before each epic, conduct diligent clarification and research, then add relevant notes directly to the epic documentation. This ensures everyone starts with the same understanding of architectural requirements.

### Recurring Issues

| Pattern | Frequency | Impact |
|---------|-----------|--------|
| **Architecture-to-Story Gap** | Critical (caused pivot) | 4 stories superseded |
| **Code Review as Only Safety Net** | Moderate | Delays when issues found late |
| **Agent Test Boilerplate** | 8/8 agent stories | ~30% repeated mock setup |
| **Line Count Targets Too Strict** | 3 stories | Had to adjust thresholds (e.g., 300→350 LOC) |

### Specific Findings

- **ForensicsAgent (7.23)** — Code review caught HIGH severity issue: failed tool executions weren't being logged as actions, violating NFR37 audit trail. Fixed before merge.
- **Line Count Friction** — Arbitrary LOC limits caused friction; thin subclass pattern adherence matters more than exact line counts.
