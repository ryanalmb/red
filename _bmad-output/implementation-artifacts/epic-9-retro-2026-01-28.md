## ⚠️ Improvement Opportunities

### 1. Algorithm Specification Gaps

The anomaly bubbling logic (9-4) wasn't fully specified in the UX design. Team had to invent the priority scoring algorithm. Consider more detailed specs for behavioral algorithms.

### 2. Magic Number Vigilance

Code review caught latency thresholds (500ms, 2000ms) that weren't named constants. Added `LATENCY_HEALTHY_MS` and `LATENCY_DEGRADED_MS`. Continue enforcing this in reviews.

### 3. Component Readiness vs Integration

Some components (Drop Box Status Panel) are ready but can't be fully tested until later epics (Epic 12). This is expected given the epic structure but worth noting.

### Key Architectural Decisions

1. **Virtualized Rendering** — Only visible rows rendered for 10K+ agent scale (NFR4)
2. **Responsive Breakpoints** — `LayoutMode` enum: COMPACT (80x24) / STANDARD (100x30) / OPTIMAL (120x40)
3. **Dual-Mode Application** — Daemon mode (TUIClient IPC) vs Standalone mode (EventBus)
4. **TCSS Theming** — UX spec color tokens (`$bg-primary`, `$cyber-green`, `$danger`) as CSS variables
5. **Component Composability** — Widgets designed for reuse across Epic 10/11

## 🎯 Key Learnings

1. **UX Spec Line References Work** — Citing specific line numbers eliminated ambiguity and reduced rework
2. **Virtualization First** — Building 10K-scale support from the start prevented costly retrofitting
3. **Component Composability** — Reusable widgets (HiveMatrix, StatusBar) accelerate future epics
4. **Magic Number Vigilance** — Code review enforcement of named constants improves maintainability
5. **Three-Epic TUI Structure** — Core (9) → Controls (10) → Data (11) proves to be clean separation
