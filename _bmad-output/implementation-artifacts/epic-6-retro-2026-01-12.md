## ✅ What Went Well

### Technical Wins
1. **Unified Embedded Vector Store** — Moving to LanceDB kept deployment footprint minimal (no external service) while handling ~70K vectors efficiently.
2. **Robust Ingestion Pipeline** — `MarkdownCodeBlockSplitter` successfully preserved code integrity from HackTricks, preventing downstream parsing errors.
3. **Knowledge Density** — Successfully integrated 6 major sources (ATT&CK, Atomic Red, HackTricks, Payloads, LOLBAS, GTFOBins) in a single sprint.
4. **Resilient Architecture** — Director integration uses non-blocking queries with graceful fallback, ensuring swarm stability even if RAG is slow.

### Process Wins
1. **Critical Integration Testing** — While difficult to implement, the comprehensive integration test suite was the only way to validate the complex multi-source ingestion and retrieval flows.
2. **Strict Status Tracking** — Adhering to the "Status Checks" action item from Epic 5 kept the board green and accurate.

## ⚠️ Challenges & Patterns

### Recurring Issues
1. **Mocking Complexity** — High effort needed to mock filesystem/network for 6 different sources (40% of dev time).
2. **Schema Churn** — Metadata schema required updates in 3 separate stories (6.1, 6.3, 6.13) rather than being defined once.
3. **Async Race Conditions** — Ingestion pipeline encountered flaky tests due to file flush timing issues.
4. **Library Overhead** — `stix2` library dependency significantly slowed down test collection time.

### Specific Challenges
1. **Story Format Regression** — The story template shifted mid-epic away from the explicit TDD-phased format (RED/GREEN/REFACTOR) that worked well in stories 1-6. This led to less structured implementation steps. **(User Critical Feedback)**
